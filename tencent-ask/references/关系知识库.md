## 关系类型说明

| 关系类型 | 含义 | 查询方向 |
|---------|------|---------|
| `contains` | 父资源包含子资源，生命周期相关 | 从父查子，用过滤器传递父ID |
| `depends_on` | 资源依赖另一资源才能工作 | 从子查父，或从父查依赖 |
| `attached_to` | 资源绑定/挂载到另一资源 | 双向可查，传递资源ID |
| `connected_to` | 资源通过网络/接口连接 | 双向，通过描述接口反查 |
| `configured_with` | 资源配置了规则/策略/触发器 | 从主资源查关联配置 |
| `deployed_in` | 资源部署在某网络/区域内 | 从资源查VPC/子网信息 |

## 一、核心关联关系图谱

```
VPC ──── Subnet ──── CVM ──── CBS (系统盘/数据盘)
  │         │          │
  │         │          ├──── EIP
  │         │          ├──── 安全组 (SecurityGroup)
  │         │          ├──── CLB (后端服务器 RS)
  │         │          └──── Monitor 监控告警
  │         │
  │         ├──── CDB (MySQL)
  │         ├──── Redis
  │         ├──── MongoDB
  │         └──── TKE 节点
  │
  ├──── NAT网关 ──── EIP (1对多)
  ├──── 路由表 ──── Subnet (关联)
  ├──── 对等连接 ──── 另一个VPC
  └──── 网络ACL ──── Subnet

CLB ──── 监听器 ──── 转发规则 ──── 后端 (CVM/SCF)
  │                               └──── 健康状态
  └──── 安全组

TKE集群 ──── 节点池 ──── CVM节点
          └──── K8s API ──── Pod/Service/Deployment

CAM ──── 角色 ──── 策略 (内联/托管)
      └──── 用户 ──── 用户组 ──── 策略

CLS ──── 日志集 ──── 日志主题 ──── 日志索引
TCR ──── 命名空间 ──── 镜像仓库 ──── 镜像Tag
CKafka ──── Topic ──── 消费组 ──── 消费偏移
```

## 二、详细关联关系

### 1. VPC → 子网

**关系类型：** `contains`（1对多）

**查询路径：**
```bash
# 获取VPC下所有子网
tccli vpc DescribeSubnets \
  --profile devops-readonly \
  --region ap-beijing \
  --Filters '[{"Name":"vpc-id","Values":["vpc-xxxxxxxx"]}]'
```

**反向查询（子网所属VPC）：**
```bash
tccli vpc DescribeSubnets \
  --profile devops-readonly \
  --region ap-beijing \
  --SubnetIds '["subnet-xxxxxxxx"]'
# 查看返回中的 VpcId 字段
```

**传递字段：** `VpcId` → `--Filters Name=vpc-id`

### 4. CVM → 安全组

**关系类型：** `attached_to`（多对多）

**查询路径：**
```bash
# Step1: 获取CVM绑定的安全组ID列表
INSTANCE_INFO=$(tccli cvm DescribeInstances \
  --profile devops-readonly \
  --region ap-beijing \
  --InstanceIds '["ins-xxxxxxxx"]')
SG_IDS=$(echo $INSTANCE_INFO | python3 -c "
import sys, json
d = json.load(sys.stdin)
sgs = d['InstanceSet'][0]['SecurityGroupIds']
print(json.dumps(sgs))
")

# Step2: 查询安全组详情及规则
tccli vpc DescribeSecurityGroupPolicies \
  --profile devops-readonly \
  --region ap-beijing \
  --SecurityGroupId "sg-xxxxxxxx"
```

**反向查询（安全组关联了哪些CVM）：**
```bash
tccli cvm DescribeInstances \
  --profile devops-readonly \
  --region ap-beijing \
  --Filters '[{"Name":"sg-id","Values":["sg-xxxxxxxx"]}]'
```

  --profile devops-readonly \

### 22. COS 存储桶 → 策略/生命周期

**关系类型：** `configured_with`

> **⚠️ 注意**：COS 不使用 `tccli`，必须使用专用的 `coscli` 工具，配置文件 `~/.cos-readonly.yaml`。

**查询路径：**
```bash
# 列出所有存储桶
coscli ls -c ~/.cos-readonly.yaml

# 列出指定存储桶内的文件
coscli ls cos://my-bucket-1250000000/ -c ~/.cos-readonly.yaml

# 递归列出所有对象（含子目录）
coscli ls cos://my-bucket-1250000000/ -r -c ~/.cos-readonly.yaml

# 查询存储桶总用量
coscli du cos://my-bucket-1250000000/ -c ~/.cos-readonly.yaml

# 查看对象元数据
coscli stat cos://my-bucket-1250000000/path/to/file.txt -c ~/.cos-readonly.yaml

# 查询Bucket版本控制状态
coscli bucket-versioning --method get cos://my-bucket-1250000000 -c ~/.cos-readonly.yaml

# 查询Bucket加密配置
coscli bucket-encryption --method get cos://my-bucket-1250000000 -c ~/.cos-readonly.yaml

# 查询Bucket访问控制（ACL）
coscli bucket-acl --method get cos://my-bucket-1250000000 -c ~/.cos-readonly.yaml
```

> **Bucket 名称格式**：`<BucketName>-<AppId>`，如 `my-bucket-1250000000`

## 三、跨服务诊断查询路径

### 诊断：为什么CVM无法访问外网

```
1. 检查CVM是否绑定EIP → vpc DescribeAddresses (Filters: instance-id)
2. 检查CVM所在子网的路由表 → vpc DescribeRouteTables (Filters: association.subnet-id)
3. 检查路由表是否有 0.0.0.0/0 指向 NAT 或互联网 → 分析路由表 RouteSet
4. 检查安全组出站规则 → vpc DescribeSecurityGroupPolicies
5. 检查网络ACL → vpc DescribeNetworkAcls (Filters: association.subnet-id)
6. 若有NAT网关，确认子网绑定了NAT → vpc DescribeNatGateways
```

### 诊断：CLB后端服务器健康状态

```
1. 查询CLB实例 → clb DescribeLoadBalancers (LoadBalancerIds)
2. 查询监听器 → clb DescribeListeners (LoadBalancerId)
3. 查询后端服务器健康状态 → clb DescribeTargetHealth (LoadBalancerIds)
4. 若不健康，检查CVM安全组是否放通CLB的探测端口
   → vpc DescribeSecurityGroupPolicies (SecurityGroupId from CVM)
5. 检查CLB访问日志 → cls DescribeTopics (logset for CLB)
```

### 诊断：CDB连接数过高

```
1. 查询CDB实例基本信息 → cdb DescribeDBInstances (InstanceIds)
2. 查询当前连接数监控 → monitor GetMonitorData
   (Namespace: QCE/CDB, MetricName: mysql_threads_connected)
3. 查询CDB参数 max_connections → cdb DescribeDBParameters
4. 查询慢查询日志 → cdb DescribeSlowLogs (最近24小时)
5. 查询CDB账号列表 → cdb DescribeAccounts
6. 查询CDB告警策略 → monitor DescribeAlarmPolicies (Namespace: QCE/CDB)
```

### 诊断：TKE集群节点不健康

```
1. 查询集群状态 → tke DescribeClusters (ClusterIds)
2. 查询节点列表和状态 → tke DescribeClusterInstances (ClusterId)
3. 查询不健康节点所属节点池 → tke DescribeClusterNodePools (ClusterId)
4. 查询对应CVM状态 → cvm DescribeInstances (Filters: instance-id)
5. 查询CVM监控数据（CPU/内存）→ monitor GetMonitorData
   (Namespace: QCE/CVM, MetricName: CPUUsage/MemUsage)
6. 检查节点安全组 → vpc DescribeSecurityGroupPolicies
```

### 诊断：CKafka消费延迟

```
1. 查询CKafka实例状态 → ckafka DescribeInstancesDetail
2. 查询消费组列表 → ckafka DescribeGroup (InstanceId)
3. 查询消费组偏移（积压量）→ ckafka DescribeGroupOffsets
4. 查询监控数据（消息堆积数）→ monitor GetMonitorData
   (Namespace: QCE/CKAFKA, MetricName: ConsumerLag)
5. 查询生产者速率 → monitor GetMonitorData (MetricName: MsgInPerSec)
```

### 诊断：Redis内存使用率过高

```
1. 查询Redis实例基本信息 → redis DescribeInstances (InstanceId)
2. 查询内存使用监控 → monitor GetMonitorData
   (Namespace: QCE/REDIS, MetricName: MemUsed/MemUtil)
3. 查询Top命令统计 → redis DescribeInstanceMonitorTopNCmd (SpanType: 1)
4. 查询key分布 → redis DescribeInstanceMonitorBigKey
5. 查询参数 maxmemory-policy → redis DescribeInstanceParams
6. 查询备份状态 → redis DescribeInstanceBackups
```

### Monitor 监控与资源的关联

| 资源类型 | Monitor Namespace | 常用指标 |
|---------|-------------------|---------|
| CVM | QCE/CVM | CPUUsage, MemUsage, LanOuttraffic |
| CDB | QCE/CDB | mysql_threads_connected, BytesSent |
| Redis | QCE/REDIS | MemUsed, MemUtil, Qps |
| CLB | QCE/LB_PRIVATE / QCE/LB_PUBLIC | InPkg, OutBandwidth, HealthyRsCount |
| TKE节点 | QCE/DOCKER | CpuUsageForNode, MemUsageForNode |
| CKafka | QCE/CKAFKA | MsgInPerSec, ConsumerLag |

# 通用Monitor查询格式
tccli monitor GetMonitorData \
  --profile devops-readonly \
  --region ap-beijing \
  --Namespace "QCE/CVM" \

  --Period 300 \

### CAM 权限关系全景

```
CAM子账号 ──── 直接绑定策略（自定义/系统）
           └── 加入用户组 ──── 组绑定策略
           └── 被角色信任 ──── 角色绑定策略

资源 ──── 服务关联角色 ──── 自动绑定服务策略
      └── 自定义角色 ──── 手动绑定策略
```

### CLB 公网与内网类型对比

| 特性 | 公网CLB | 内网CLB |
|------|---------|---------|
| LoadBalancerType | OPEN | INTERNAL |
| VIP | 公网IP | VPC内网IP |
| 安全组 | 有（控制访问） | 可选 |
| 跨地域绑定 | 支持 | 不支持 |
| Namespace | QCE/LB_PUBLIC | QCE/LB_PRIVATE |
