### 关系类型标准化说明

1. **contains** (包含)
   - 表示一个资源包含另一个资源
   - 例如：VPC 包含 Subnet、EKS Cluster 包含 NodeGroup

2. **depends_on** (依赖)
   - 表示一个资源依赖于另一个资源
   - 例如：EC2 依赖于 VPC、Lambda 依赖于 IAM Role

3. **attached_to** (附着/绑定)
   - 表示一个资源物理或逻辑附着到另一个资源
   - 例如：EBS Volume 挂载到 EC2、EIP 绑定到 EC2

4. **connected_to** (连接)
   - 表示两个资源之间存在连接关系
   - 例如：ELB 连接到 EC2 目标组、Lambda 访问 RDS

5. **configured_with** (配置)
   - 表示一个资源配置了某种功能或策略
   - 例如：EC2 配置了安全组、Lambda 配置了 IAM 角色

## 1. EC2 - 弹性计算云
核心资源：实例 (Instance)
角色：计算节点，承载应用程序。

### 核心关系

**网络归属 (位于)**
关系：depends_on (EC2 -> VPC)
路径：EC2 -> Subnet -> VPC
描述：EC2 实例必须部署在 VPC 内的 Subnet 中，继承 VPC 的网络隔离。
关联字段：SubnetId (EC2) -> VpcId (Subnet)
查询示例："EC2 i-xxx 所在的 VPC"、"VPC vpc-xxx 下有哪些 EC2"
CLI 路径：
  1. `aws ec2 describe-instances --instance-ids i-xxx --query 'Reservations[].Instances[].SubnetId'`
  2. `aws ec2 describe-subnets --subnet-ids subnet-xxx --query 'Subnets[].VpcId'`

**存储挂载 (挂载)**
关系：attached_to (EBS Volume -> EC2)
描述：EC2 可以挂载多块 EBS 存储卷（根卷/数据卷）。
关联字段：Attachments[].InstanceId (Volume)
查询示例："EC2 i-xxx 挂载了哪些存储卷"、"vol-xxx 挂载在哪台 EC2 上"
CLI：`aws ec2 describe-volumes --filters "Name=attachment.instance-id,Values=i-xxx"`

**安全配置 (配置)**
关系：configured_with (EC2 -> SecurityGroup)
描述：EC2 必须关联至少一个安全组，用于控制网络访问规则。
关联字段：SecurityGroups[].GroupId (EC2)
查询示例："EC2 i-xxx 关联了哪些安全组"
CLI：`aws ec2 describe-instances --instance-ids i-xxx --query 'Reservations[].Instances[].SecurityGroups'`

**公网访问 (绑定)**
关系：attached_to (EIP -> EC2)
描述：EC2 可以绑定弹性IP（EIP）以实现固定公网访问。
关联字段：InstanceId (EIP 关联信息)
查询示例："EC2 i-xxx 绑定了哪些 EIP"、"EIP eipalloc-xxx 绑定了哪个实例"
CLI：`aws ec2 describe-addresses --filters "Name=instance-id,Values=i-xxx"`

**IAM 权限 (配置)**
关系：configured_with (EC2 -> IAM Role)
描述：EC2 可以关联 IAM 实例配置文件，赋予实例访问 AWS 服务的权限。
关联字段：IamInstanceProfile.Arn (EC2)
查询示例："EC2 i-xxx 使用的 IAM 角色是什么"
CLI：`aws ec2 describe-instances --instance-ids i-xxx --query 'Reservations[].Instances[].IamInstanceProfile'`

### 扩展关系

**监控**
关系：configured_with (EC2 -> CloudWatch)
数据：CPUUtilization, NetworkIn/Out, DiskRead/Write 等

**负载均衡后端 (作为)**
关系：connected_to (ELBv2 TargetGroup -> EC2)

**容器节点 (作为)**
关系：contains (EKS NodeGroup/ECS Cluster -> EC2)

**Auto Scaling (属于)**
关系：contains (AutoScalingGroup -> EC2)
CLI：`aws autoscaling describe-auto-scaling-instances --instance-ids i-xxx`

## 2. Lambda - 无服务器函数
核心资源：函数 (Function)
角色：事件驱动的无服务器计算单元。

### 核心关系

**IAM 执行角色 (依赖)**
关系：depends_on (Lambda -> IAM Role)
描述：Lambda 函数必须有一个执行角色，用于访问 AWS 服务。
关联字段：Role (Function 配置)
CLI：`aws lambda get-function-configuration --function-name my-func --query Role`

**VPC 配置 (可选)**
关系：depends_on (Lambda -> VPC/Subnet/SecurityGroup)
描述：Lambda 可以配置 VPC 访问，从而访问 VPC 内的 RDS、ElastiCache 等资源。
关联字段：VpcConfig (Function 配置)
CLI：`aws lambda get-function-configuration --function-name my-func --query VpcConfig`

**事件源触发 (由...触发)**
关系：configured_with (Lambda <- S3/SQS/SNS/DynamoDB/Kinesis/EventBridge/API Gateway)
描述：Lambda 可以被多种事件源触发执行。
CLI：`aws lambda list-event-source-mappings --function-name my-func`

**访问其他服务**
关系：connected_to (Lambda -> RDS/S3/DynamoDB/SQS/SNS/ElastiCache/...)
描述：函数逻辑中常调用其他 AWS 服务 API 或访问其资源。

**层 (依赖)**
关系：depends_on (Lambda -> Layer)
描述：Lambda 函数可以使用层来共享代码、库和依赖。
CLI：`aws lambda get-function-configuration --function-name my-func --query Layers`

## 3. ECS - 弹性容器服务
核心资源：集群 (Cluster)、服务 (Service)、任务 (Task)
角色：托管容器编排，支持 EC2 和 Fargate 两种启动类型。

### 核心关系

**基础设施依赖**
关系：depends_on (ECS Cluster -> VPC/EC2 或 Fargate)
- EC2 启动类型：集群包含 EC2 容器实例
- Fargate 启动类型：AWS 托管底层基础设施
CLI（集群详情）：`aws ecs describe-clusters --clusters my-cluster`

**服务与任务**
关系：contains (ECS Cluster -> Service -> Task)
描述：集群包含服务，服务管理任务（容器组）的数量和部署。
CLI：
  1. `aws ecs list-services --cluster my-cluster`
  2. `aws ecs list-tasks --cluster my-cluster --service-name my-service`

**任务定义 (依赖)**
关系：depends_on (ECS Task -> TaskDefinition)
描述：任务基于任务定义运行，定义了容器镜像、资源、环境变量等。
CLI：`aws ecs describe-task-definition --task-definition my-task:1`

**负载均衡集成**
关系：connected_to (ECS Service -> ELBv2 TargetGroup)
描述：ECS 服务可以关联 ALB/NLB 目标组，实现流量分发。
CLI：`aws ecs describe-services --cluster my-cluster --services my-service --query 'services[].loadBalancers'`

**ECR 镜像**
关系：depends_on (ECS TaskDefinition -> ECR Repository)
描述：任务定义中的容器镜像通常存储在 ECR。

## 4. EKS - Kubernetes 服务
核心资源：集群 (Cluster)
角色：托管 Kubernetes 集群。

### 核心关系

**基础设施依赖**
关系：depends_on (EKS Cluster -> VPC/Subnet)
描述：EKS 控制平面和节点部署在 VPC 中。
CLI：`aws eks describe-cluster --name my-cluster --query 'cluster.resourcesVpcConfig'`

**节点组 (包含)**
关系：contains (EKS Cluster -> NodeGroup -> EC2)
描述：节点组管理 EC2 工作节点。
CLI：`aws eks describe-nodegroup --cluster-name my-cluster --nodegroup-name ng-xxx`

**Fargate Profile (包含)**
关系：contains (EKS Cluster -> FargateProfile)
CLI：`aws eks describe-fargate-profile --cluster-name my-cluster --fargate-profile-name fp-xxx`

**IAM OIDC (依赖)**
关系：depends_on (EKS -> IAM OIDC Provider)
描述：用于 Pod 级别的 IAM 权限 (IRSA)。

**负载均衡集成**
关系：connected_to (EKS Service/Ingress -> ELBv2)
描述：Kubernetes Service (LoadBalancer 类型) 或 Ingress 自动创建 ALB/NLB。

## 5. RDS - 关系型数据库
核心资源：数据库实例 (DBInstance)、Aurora 集群 (DBCluster)
角色：托管关系型数据库服务。

### 核心关系

**网络归属 (位于)**
关系：depends_on (RDS -> VPC/SubnetGroup)
描述：RDS 实例部署在 VPC 的 DB 子网组中。
CLI：`aws rds describe-db-instances --db-instance-identifier mydb --query 'DBInstances[].DBSubnetGroup'`

**安全访问控制**
关系：configured_with (RDS -> SecurityGroup)
描述：RDS 关联的安全组控制哪些来源可以访问数据库端口。
CLI：`aws rds describe-db-instances --db-instance-identifier mydb --query 'DBInstances[].VpcSecurityGroups'`

**应用连接**
关系：connected_to (EC2/Lambda/ECS/EKS -> RDS)
描述：应用程序通过 RDS 端点连接数据库，通常在同一 VPC 内。
查询示例："哪些 EC2 可以连接到 RDS mydb"（通过安全组规则推断）

**备份存储**
关系：configured_with (RDS -> S3 - 自动备份)
描述：RDS 自动备份存储在 AWS 管理的 S3，手动快照可导出到用户 S3。
CLI：`aws rds describe-db-snapshots --db-instance-identifier mydb`

**Aurora 集群关系**
关系：contains (Aurora Cluster -> DBInstance)
描述：Aurora 集群包含写入实例和只读实例。
CLI：
  1. `aws rds describe-db-clusters --db-cluster-identifier my-aurora`
  2. `aws rds describe-db-instances --filters "Name=db-cluster-id,Values=my-aurora"`

**加密密钥**
关系：configured_with (RDS -> KMS Key)
描述：加密的 RDS 实例使用 KMS 密钥。
CLI：`aws rds describe-db-instances --db-instance-identifier mydb --query 'DBInstances[].KmsKeyId'`

## 6. DynamoDB - NoSQL 数据库
核心资源：表 (Table)
角色：全托管无服务器 NoSQL 数据库。

### 核心关系

**应用访问**
关系：connected_to (EC2/Lambda/ECS -> DynamoDB)
描述：应用通过 AWS SDK 访问 DynamoDB，通常通过 IAM 权限控制。

**全局表 (复制)**
关系：contains (GlobalTable -> Regional Table)
描述：全局表在多个区域保持同步副本。
CLI：`aws dynamodb describe-table --table-name my-table --query 'Table.Replicas'`

**流 (包含)**
关系：contains (DynamoDB Table -> Stream)
描述：DynamoDB Streams 捕获表的变更事件，可触发 Lambda。
CLI：`aws dynamodb describe-table --table-name my-table --query 'Table.StreamSpecification'`

**加密**
关系：configured_with (DynamoDB -> KMS Key)

## 7. ElastiCache - 内存缓存
核心资源：Redis 复制组 (ReplicationGroup) / Memcached 集群 (CacheCluster)
角色：高性能内存缓存服务。

### 核心关系

**网络归属**
关系：depends_on (ElastiCache -> VPC/SubnetGroup)
CLI：`aws elasticache describe-replication-groups --replication-group-id my-redis --query 'ReplicationGroups[].NodeGroups'`

**安全访问控制**
关系：configured_with (ElastiCache -> SecurityGroup)
CLI：`aws elasticache describe-replication-groups --replication-group-id my-redis --query 'ReplicationGroups[].SecurityGroups'`

**应用访问**
关系：connected_to (EC2/Lambda/ECS/EKS -> ElastiCache)
描述：应用通过 Redis/Memcached 端点连接缓存，通常需要同 VPC。

## 8. ELBv2 - 应用/网络负载均衡
核心资源：负载均衡器 (LoadBalancer)、目标组 (TargetGroup)、监听器 (Listener)
角色：流量分发入口，支持 ALB (七层) 和 NLB (四层)。

### 核心关系

**网络部署**
关系：depends_on (ELBv2 -> VPC/Subnet)
描述：负载均衡器部署在 VPC 的多个可用区子网中。
CLI：`aws elbv2 describe-load-balancers --names my-alb --query 'LoadBalancers[].AvailabilityZones'`

**安全配置 (ALB)**
关系：configured_with (ALB -> SecurityGroup)
描述：ALB 需要安全组，NLB 不需要。
CLI：`aws elbv2 describe-load-balancers --names my-alb --query 'LoadBalancers[].SecurityGroups'`

**监听器 (入口)**
关系：contains (ELBv2 -> Listener -> Rule)
描述：负载均衡器包含监听器，监听器包含转发规则。
CLI：
  1. `aws elbv2 describe-listeners --load-balancer-arn <arn>`
  2. `aws elbv2 describe-rules --listener-arn <arn>`

**目标组 (后端)**
关系：connected_to (ELBv2 Rule -> TargetGroup -> EC2/Lambda/ECS)
描述：规则转发流量到目标组，目标组包含后端实例。
CLI：
  1. `aws elbv2 describe-target-groups --load-balancer-arn <arn>`
  2. `aws elbv2 describe-target-health --target-group-arn <arn>`

**证书配置 (ALB HTTPS)**
关系：configured_with (ALB Listener -> ACM Certificate)
CLI：`aws elbv2 describe-listener-certificates --listener-arn <arn>`

**WAF 关联**
关系：configured_with (ALB -> WAF WebACL)
描述：ALB 可以关联 WAF WebACL 进行 Web 防护。
CLI：`aws wafv2 get-web-acl-for-resource --resource-arn <alb-arn>`

**ECS/EKS 集成**
关系：connected_to (ECS Service/EKS Ingress -> ELBv2 TargetGroup)

## 9. VPC - 虚拟私有云
核心资源：VPC、子网 (Subnet)、路由表 (RouteTable)
角色：AWS 网络隔离的核心枢纽。

### 核心关系 (包含)

**包含子网**
关系：contains (VPC -> Subnet)
描述：VPC 包含多个子网，每个子网属于一个可用区。
CLI：`aws ec2 describe-subnets --filters "Name=vpc-id,Values=vpc-xxx"`

**包含路由表**
关系：contains (VPC -> RouteTable)
CLI：`aws ec2 describe-route-tables --filters "Name=vpc-id,Values=vpc-xxx"`

**包含安全组**
关系：contains (VPC -> SecurityGroup)
CLI：`aws ec2 describe-security-groups --filters "Name=vpc-id,Values=vpc-xxx"`

**包含网络 ACL**
关系：contains (VPC -> NetworkACL)
CLI：`aws ec2 describe-network-acls --filters "Name=vpc-id,Values=vpc-xxx"`

### 核心关系 (连接)

**Internet 访问**
关系：connected_to (VPC -> Internet Gateway)
描述：公有子网通过 Internet Gateway (IGW) 访问公网。
CLI：`aws ec2 describe-internet-gateways --filters "Name=attachment.vpc-id,Values=vpc-xxx"`

**NAT 访问**
关系：contains (VPC -> NAT Gateway)
描述：私有子网通过 NAT Gateway 访问公网（出站流量）。
CLI：`aws ec2 describe-nat-gateways --filter "Name=vpc-id,Values=vpc-xxx"`

**VPC 对等连接**
关系：connected_to (VPC <-> VPC, Peering)
CLI：`aws ec2 describe-vpc-peering-connections --filters "Name=requester-vpc-info.vpc-id,Values=vpc-xxx"`

**Transit Gateway**
关系：connected_to (VPC -> Transit Gateway)
CLI：`aws ec2 describe-transit-gateway-vpc-attachments --filters "Name=vpc-id,Values=vpc-xxx"`

**VPC 端点**
关系：contains (VPC -> VPC Endpoint -> S3/DynamoDB/...)
描述：VPC 端点允许 VPC 内资源私网访问 AWS 服务（无需 IGW/NAT）。
CLI：`aws ec2 describe-vpc-endpoints --filters "Name=vpc-id,Values=vpc-xxx"`

**承载所有资源**
关系：contains (VPC -> EC2/RDS/ElastiCache/Lambda-VPC/ECS/EKS/ELBv2/...)
描述：绝大多数 AWS 资源部署在 VPC 内。

## 10. S3 - 对象存储
核心资源：存储桶 (Bucket)、对象 (Object)
角色：全球可用的对象存储，无需 VPC。

### 核心关系

**内容托管**
关系：configured_with (S3 Bucket -> CloudFront Distribution)
描述：S3 Bucket 常作为 CloudFront 源站，托管静态网站或资源。

**备份存储**
关系：configured_with (RDS/EBS -> S3 - 导出备份)
关系：configured_with (EC2/ECS/EKS -> S3 - 应用数据)

**Lambda 触发**
关系：configured_with (S3 -> Lambda - 事件触发)
描述：S3 对象创建/删除事件可触发 Lambda 函数。
CLI：`aws s3api get-bucket-notification-configuration --bucket my-bucket`

**访问控制**
关系：configured_with (S3 Bucket -> Bucket Policy/ACL/PublicAccessBlock)
描述：多层访问控制：Bucket Policy、ACL、Block Public Access。
CLI：
  1. `aws s3api get-bucket-policy --bucket my-bucket`
  2. `aws s3api get-public-access-block --bucket my-bucket`

**加密**
关系：configured_with (S3 Bucket -> KMS Key / SSE-S3)
CLI：`aws s3api get-bucket-encryption --bucket my-bucket`

**日志记录**
关系：configured_with (S3 Bucket -> S3 Bucket - 日志目标)
关系：configured_with (S3 Bucket -> CloudTrail - API 日志)

## 11. Route53 - DNS 服务
核心资源：托管区域 (HostedZone)、记录 (ResourceRecordSet)
角色：权威 DNS 服务。

### 核心关系

**指向 AWS 资源**
关系：connected_to (Route53 Record -> ELBv2/EC2 EIP/CloudFront/S3/...)
描述：A/CNAME 记录将域名解析到 AWS 资源的 IP 或 DNS 名称。
查询示例："域名 example.com 的 A 记录指向哪个 ALB"
CLI：`aws route53 list-resource-record-sets --hosted-zone-id Z1234567890 --query 'ResourceRecordSets[?Type==\`A\`]'`

**健康检查**
关系：configured_with (Route53 Record -> HealthCheck)
描述：路由策略（故障转移、权重等）可关联健康检查。
CLI：`aws route53 list-health-checks`

## 12. CloudWatch - 监控服务
核心资源：告警 (Alarm)、日志组 (LogGroup)
角色：统一监控、日志和告警平台。

### 核心关系

**监控所有资源**
关系：configured_with (CloudWatch -> EC2/RDS/Lambda/ELB/...)
描述：CloudWatch 提供几乎所有 AWS 服务的指标监控。

**日志收集**
关系：connected_to (CloudWatch Logs <- EC2/Lambda/ECS/EKS/RDS/...)
描述：应用和 AWS 服务将日志发送到 CloudWatch Logs。
CLI：`aws logs describe-log-groups --log-group-name-prefix /aws/lambda/`

**告警通知**
关系：configured_with (CloudWatch Alarm -> SNS Topic)
描述：告警触发后通过 SNS 发送通知。
CLI：`aws cloudwatch describe-alarms --query 'MetricAlarms[].AlarmActions'`

**Lambda 触发**
关系：configured_with (CloudWatch Events/EventBridge -> Lambda)
描述：定时任务或事件规则可触发 Lambda。

## 13. IAM - 身份权限管理
核心资源：用户 (User)、角色 (Role)、策略 (Policy)
角色：AWS 资源的访问控制中枢。

### 核心关系

**用户权限**
关系：configured_with (IAM User -> Policy/Group)
描述：用户通过附加策略或加入组来获得权限。
CLI：
  1. `aws iam list-attached-user-policies --user-name myuser`
  2. `aws iam list-groups-for-user --user-name myuser`

**角色信任关系**
关系：configured_with (IAM Role -> Trust Policy)
描述：信任策略定义谁可以扮演该角色（EC2、Lambda、ECS Task 等）。
CLI：`aws iam get-role --role-name my-role --query 'Role.AssumeRolePolicyDocument'`

**服务授权**
关系：configured_with (EC2/Lambda/ECS/EKS -> IAM Role)
描述：AWS 服务通过关联 IAM 角色获得访问其他服务的权限。

**策略版本**
关系：contains (IAM Policy -> PolicyVersion)
描述：自定义策略可以有多个版本，一个为当前版本。
CLI：`aws iam list-policy-versions --policy-arn arn:aws:iam::xxx:policy/my-policy`

## 14. KMS - 密钥管理
核心资源：密钥 (Key)
角色：加密密钥的统一管理。

### 核心关系

**加密服务**

角色：全托管 Apache Kafka 消息流服务，用于实时数据管道和流处理。

### 核心关系

**网络归属 (位于)**
关系：depends_on (MSK Cluster -> VPC/Subnet)
描述：MSK 集群的 Broker 节点部署在 VPC 子网中，每个可用区各部署一个 Broker。

关系：connected_to (EC2/Lambda/ECS/EKS -> MSK Cluster)

关系：configured_with (MSK Cluster -> CloudWatch)
描述：MSK 自动向 CloudWatch 发送 Broker 和主题级别指标（CPU、磁盘、网络、消费者延迟等）。

## 17. Auto Scaling - EC2 自动扩缩容
核心资源：Auto Scaling 组 (AutoScalingGroup)
角色：根据负载自动调整 EC2 实例数量，与 ELB 结合实现弹性伸缩。

**包含 EC2 实例**

描述：ASG 可使用 EC2 系统检查或 ELB 健康检查来判断实例是否健康，不健康的实例会被自动替换。

## 18. IAM Identity Center - 单点登录/统一身份
核心资源：Instance（SSO实例）、PermissionSet（权限集）、AccountAssignment（账号分配）、User、Group
角色：集中管理多 AWS 账号的用户身份和访问权限，替代手动创建 IAM 用户。

> **⚠️ 示例账号配置**: IAM Identity Center 部署在 `eu-north-1` 区域
> - Instance ARN: `arn:aws:sso:::instance/ssoins-0123456789abcdef0`
> - Identity Store ID: `d-0123456789`

### 核心关系

**授权 AWS 账号访问 (分配)**
关系：configured_with (PermissionSet -> AccountAssignment -> IAM Role in target account)
描述：权限集被分配给用户/组后，用户登录时在目标账号内自动获得对应的临时 IAM 角色。
查询示例："账号下有哪些用户/组被授权了什么权限集"
CLI：
  1. `aws sso-admin list-permission-sets-provisioned-to-account --instance-arn arn:aws:sso:::instance/ssoins-0123456789abcdef0 --account-id 123456789012 --region eu-north-1 --profile devops-readonly`
  2. `aws sso-admin list-account-assignments --instance-arn arn:aws:sso:::instance/ssoins-0123456789abcdef0 --account-id 123456789012 --permission-set-arn <arn> --region eu-north-1 --profile devops-readonly`

**权限集附加策略 (配置)**
关系：configured_with (PermissionSet -> IAM Managed Policy / Inline Policy)
描述：权限集通过附加 AWS 托管策略或自定义内联策略来定义实际权限范围。
CLI：
  - `aws sso-admin list-managed-policies-in-permission-set --instance-arn arn:aws:sso:::instance/ssoins-0123456789abcdef0 --permission-set-arn <arn> --region eu-north-1 --profile devops-readonly`
  - `aws sso-admin get-inline-policy-for-permission-set --instance-arn arn:aws:sso:::instance/ssoins-0123456789abcdef0 --permission-set-arn <arn> --region eu-north-1 --profile devops-readonly`

**用户与组成员关系 (包含)**
关系：contains (Group -> User, via identitystore)
描述：SSO 用户可以加入多个 SSO 组，组可以被批量授权权限集，简化权限管理。
CLI：
  - `aws identitystore list-group-memberships --identity-store-id d-0123456789 --group-id <group-id> --region eu-north-1 --profile devops-readonly`
  - `aws identitystore list-group-memberships-for-member --identity-store-id d-0123456789 --member-id UserId=<user-id> --region eu-north-1 --profile devops-readonly`

**与传统 IAM 的关系**
关系：IAM Identity Center 与 IAM 是独立的两套身份体系
- IAM Identity Center 用户 ≠ IAM 用户（不同服务，不同 ID）
- 登录后生成的是**临时凭证**（STS AssumeRole），不是 IAM 用户的长期凭证
- 审计日志在 CloudTrail 中，事件源为 `sso.amazonaws.com`



### 类型对比

**ALB (Application Load Balancer)**
- 七层（HTTP/HTTPS/WebSocket/gRPC）负载均衡
- 支持基于路径、主机头、HTTP 头、查询字符串的内容路由
- 需要安全组
- 支持 WAF 集成
- 支持 Lambda 作为目标
- 固定 DNS 名称（非固定IP）

**NLB (Network Load Balancer)**
- 四层（TCP/UDP/TLS）负载均衡
- 极低延迟，高吞吐量
- 不需要安全组（直接透传）
- 支持固定 EIP（固定IP）
- 支持 TCP 透传（保持客户端 IP）
- 适用于非 HTTP 协议（数据库、游戏、IoT 等）

### 关键查询差异

```bash
# 判断 LB 类型（Type 字段：application 或 network）
aws elbv2 describe-load-balancers --profile devops-readonly --region ap-southeast-1 \
  | jq '.LoadBalancers[] | {Name, Type, DNSName, State: .State.Code}'

# ALB 安全组（NLB 没有安全组字段）
aws elbv2 describe-load-balancers \
  --names my-alb \
  --query 'LoadBalancers[].SecurityGroups' \
  --profile devops-readonly --region ap-southeast-1

# NLB 固定 IP（通过关联的 EIP 查询）
aws ec2 describe-addresses \
  --filters "Name=network-interface-owner-id,Values=<aws-nlb-account>" \
  --profile devops-readonly --region ap-southeast-1
```

## 20. MemoryDB - Redis 兼容持久化内存数据库
核心资源：集群(Cluster)、分片(Shard)、节点(Node)
角色：提供持久化的 Redis 兼容数据库，数据写入多可用区持久日志，不丢失。

### 核心关系

**网络归属 (位于)**
关系：depends_on (MemoryDB Cluster -> VPC/SubnetGroup)
描述：MemoryDB 集群部署在 VPC 子网组中，支持多可用区高可用。

描述：应用通过集群端点连接，端口默认 6379，需在同一 VPC 或有 VPC Peering。

**与 ElastiCache 的区别**
- MemoryDB: 数据持久化，多可用区写入日志，可用作主数据库
