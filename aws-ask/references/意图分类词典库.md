# AWS 云资源意图分类词典

## 一、分类体系概述
本词典定义了 AWS 云资源查询场景的完整意图分类体系，旨在为自然语言查询提供标准化的意图识别依据。

## 二、一级分类（主意图）

### 1. 简单查询 (SIMPLE_QUERY)
特征: 单一资源、单次 CLI 调用、明确标识符、无复杂关联

典型查询: "查看 EC2 实例 i-0xxx 的详情"
处理复杂度: ⭐☆☆☆☆
API调用数: 1
输出模式: 单实例详情

### 2. 关联查询 (ASSOCIATION_QUERY)
特征: 涉及资源间关系、需要关联数据、多重依赖

典型查询: "EC2 i-0xxx 挂载了哪些 EBS 存储卷"
处理复杂度: ⭐⭐⭐☆☆
API调用数: 2-3
输出模式: 主从式关系树

### 3. 复合查询 (COMPOUND_QUERY)
特征: 多维度条件、多服务聚合、需要数据计算

典型查询: "统计所有区域的 EC2 实例总数和类型分布"
处理复杂度: ⭐⭐⭐⭐☆
API调用数: 3-5
输出模式: 聚合统计视图

### 4. 诊断查询 (DIAGNOSTIC_QUERY)
特征: 隐含问题检测、状态检查、配置审计、安全分析

典型查询: "检查所有安全组是否有高危端口对 0.0.0.0/0 开放"
处理复杂度: ⭐⭐⭐⭐☆
API调用数: 2-4 + 规则引擎
输出模式: 诊断报告

### 5. 对比查询 (COMPARISON_QUERY)
特征: 多资源/状态对比、差异分析、趋势比较

典型查询: "对比生产和测试环境 EC2 实例的配置"
处理复杂度: ⭐⭐⭐☆☆
API调用数: 2
输出模式: 比较表格

### 6. 运维操作建议 (OPERATIONAL_QUERY)
特征: 隐含运维需求、优化建议、最佳实践

典型查询: "如何优化我的 RDS 数据库性能"
处理复杂度: ⭐⭐⭐⭐☆
API调用数: 1-3 + 知识库
输出模式: 操作建议清单

## 四、分类特征维度

### 复杂度维度

| 复杂度等级 | API调用数 | 特征 | 执行方式 |
|---------|---------|------|---------|
| L1-极简 | 1 | 单资源、明确ID | 直接执行 |
| L2-简单 | 1-2 | 单资源或简单关联 | 直接执行 |
| L3-中等 | 2-3 | 多步骤或简单聚合 | 分步执行 |
| L4-复杂 | 3-5 | 多服务关联或批量 | 分阶段执行 |
| L5-极复杂 | 5+ | 多区域/跨服务/诊断 | 分阶段+汇总 |

### AWS 特有复杂度因素

| 因素 | 说明 | 复杂度影响 |
|------|------|---------|
| 多区域查询 | 需要循环遍历多个区域 | +1 级 |
| ARN 解析 | 需要从 ARN 提取信息进行下一步查询 | +0.5 级 |
| 分页处理 | 资源数量大需要多次翻页 | +0.5 级 |
| 标签过滤 | 通过标签批量识别和过滤资源 | 通常简单 |
| IAM 权限链 | 追溯完整权限链路 | +2 级 |

## 五、分类决策树

### 意图识别流程图

```
开始
  ↓
用户输入自然语言查询
  ↓
[第一步：操作类型识别]
  ├── 包含写操作词（创建、删除、修改、停止）→ 拒绝并说明只读限制
  ├── 包含具体ID/名称 → 转向 SIMPLE_* 分支
  ├── 包含"关系词"（的、属于、挂载、连接等）→ 转向 ASSOC_* 分支
  ├── 包含"统计词"（统计、总共、所有区域等）→ 转向 COMPOUND_* 分支
  ├── 包含"诊断词"（检查、为什么、安全、合规）→ 转向 DIAG_* 分支
  ├── 包含"对比词"（对比、vs、差异）→ 转向 COMPARE_* 分支
  └── 包含"建议词"（如何、怎么、建议）→ 转向 OPS_* 分支
  ↓
[第二步：服务识别]
  ├── 明确服务（EC2/S3/RDS/...）→ 直接映射
  ├── 服务同义词（服务器→EC2、桶→S3）→ 通过同义词映射
  └── 模糊描述 → 推断最可能的服务
  ↓
[第三步：区域识别]
  ├── 用户明确指定区域 → 使用指定区域
  ├── 资源 ID 包含区域信息（ARN）→ 从 ARN 提取
  └── 未指定 → 默认 ap-southeast-1，可询问用户
  ↓
[第四步：复杂度评估]
  ├── 涉及服务数=1, 单资源 → L1/L2
  ├── 涉及服务数=1, 多资源/关联 → L2/L3
  ├── 涉及服务数=2 → L3/L4
  ├── 涉及服务数>2 或跨区域 → L4/L5
  └── 诊断/审计类 → L4/L5
  ↓
输出最终意图分类(主意图.子意图.复杂度.服务)
```

### 示例分类过程

**查询**: "检查所有 S3 Bucket 是否启用了加密"

- 检测词："检查"、"是否启用"→ DIAG_COMPLIANCE
- 服务：S3
- 区域：S3全局
- 复杂度：需要列出所有 Bucket 再逐一检查 → L3
- 最终分类：`DIAGNOSTIC_QUERY.DIAG_COMPLIANCE.L3.S3`

**查询**: "ap-southeast-1 和 us-west-2 里运行中的所有 EC2 实例，按实例类型统计数量"

- 检测词："统计"、"数量"→ COMPOUND_AGGREGATE
- 涉及服务：EC2（单一服务，多区域）
- 区域：多区域 → 复杂度+1
- 复杂度：两个区域查询+聚合 → L4
- 最终分类：`COMPOUND_QUERY.COMPOUND_MULTI_REGION+COMPOUND_AGGREGATE.L4.EC2`

## 九、测试问题与分类结果样例

1. **查看 EC2 实例 i-0123456789abcdef0 的详细信息**

   分类结果：
   - 主意图：SIMPLE_QUERY
   - 子意图：SIMPLE_INSTANCE
   - 复杂度：L1
   - 服务：EC2

2. **我的那台 web 服务器还在运行吗？**

   分类结果：
   - 主意图：SIMPLE_QUERY
   - 子意图：SIMPLE_STATUS（需上下文推测）
   - 复杂度：L2（需要通过名称标签查找）
   - 服务：EC2
